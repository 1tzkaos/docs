---
title: "GraphQL"
description: "GraphQL endpoint for OHLCV candles and the protocol list: several candle series in one round-trip."
---

The GraphQL endpoint serves two root fields: `candles`, the OHLCV candles of one pool, and `protocols`, the list of protocols. It is a small subset of the REST surface: swaps, trader stats, tokens, holders and everything else are REST only. Use GraphQL when you want several candle series (and the protocol list) in one round-trip, and REST for everything else.

## Endpoint

```
POST https://api.dexploit.dev/graphql
Content-Type: application/json
X-API-Key: ohlcv_live_sk_<your_key>
```

`Authorization: Bearer ohlcv_live_sk_<your_key>` works too. There is no hosted query builder: use any GraphQL client (or `curl`) against this URL with your key header.

## Schema

| Field | Arguments | Returns |
| --- | --- | --- |
| `candles` | `pairAddress: String!` (the pool; `pair_address` in REST), `timeframe: String!` (`1s`, `30s`, `1m`, `5m`, `15m`, `1h`, `4h` or `1d`), `start: String`, `end: String` (RFC 3339 timestamps; `end` defaults to now), `limit: Int` (default `1000`, at most `10000`) | `[GqlCandle!]!`, **oldest first** |
| `protocols` | none | `[String!]!` |

A `GqlCandle` has `timestamp`, `pairAddress`, `tokenAddress`, `baseMint`, `timeframe`, `open`, `high`, `low`, `close`, `volumeSol`, `volumeToken`, `tradeCount`, `buyCount`, `sellCount` and `uniqueTraders`: the fields of [`GET /api/v1/candles`](/api-reference), with the same values and units, in GraphQL's camelCase (`volumeSol` is REST's `volume_sol`).

A request reads at most about **10,000 candles in total**. That's the sum of `limit` over every `candles` in it, aliases included, so two aliases of `6000` are refused as one request. The exact ceiling is 10,500, shared with the request's other fields. A `limit` outside `1`–`10000` is refused with `limit must be <= 10000` (or `limit must be positive`), as it is on REST.

<Warning>
`candles` returns candles **oldest first**, starting at `start`. Without `start` it starts at the pool's **first** candle, so `limit: 60` returns the pool's oldest hour, not its latest. Pass `start` to get a recent window.
</Warning>

## Sample queries

### The last hour of 1-minute candles

```graphql
query RecentCandles($pair: String!, $start: String!) {
  candles(pairAddress: $pair, timeframe: "1m", start: $start, limit: 60) {
    timestamp
    open
    high
    low
    close
    volumeSol
    tradeCount
  }
}
```

Variables:

```json
{ "pair": "7XawhbbxtsRcQA8KTkHT9f9nc6d69UwqCDh6U5EEbEmX", "start": "2026-09-26T04:40:00Z" }
```

### Two timeframes and the protocol list in one round-trip

Aliases (`minute:`, `hourly:`) let one request ask for the same field twice.

```graphql
query Overview($pair: String!, $lastHour: String!, $lastDay: String!) {
  minute: candles(pairAddress: $pair, timeframe: "1m", start: $lastHour, limit: 60) {
    timestamp
    close
    volumeSol
  }
  hourly: candles(pairAddress: $pair, timeframe: "1h", start: $lastDay, limit: 24) {
    timestamp
    open
    high
    low
    close
  }
  protocols
}
```

Variables:

```json
{
  "pair": "7XawhbbxtsRcQA8KTkHT9f9nc6d69UwqCDh6U5EEbEmX",
  "lastHour": "2026-09-26T04:40:00Z",
  "lastDay": "2026-09-25T05:40:00Z"
}
```

### The protocol list

```graphql
{ protocols }
```

## Schema introspection

Standard GraphQL introspection works. From the command line:

```bash
curl -X POST -H 'X-API-Key: ohlcv_live_sk_<your_key>' \
  -H 'Content-Type: application/json' \
  https://api.dexploit.dev/graphql \
  -d '{"query":"{ __schema { types { name } } }"}'
```

## Errors

An error inside a well-formed query comes back as HTTP `200` with the GraphQL `errors` array. A request body that is not valid JSON is rejected before it runs, with HTTP `400` and the REST [error envelope](/concepts/quotas-errors#response-envelope) (`INVALID_PARAM`).

## When to use GraphQL vs REST

| Need | Use |
| --- | --- |
| One resource, paginate, possibly cache | REST |
| Several candle series (and the protocol list) in one round-trip | GraphQL |
| Swaps, trader stats, tokens, holders and everything else | REST only |
| WebSocket-style subscriptions | [WebSocket](/streaming/websocket), not GraphQL subscriptions |
