title: "GraphQL"
description: "GraphQL endpoint for OHLCV candles, the protocol list and swaps, trader and token reads: several of them in one round-trip."
---

The GraphQL endpoint serves `candles` (the OHLCV candles of one pool), `protocols` (the list of protocols) and the swaps roots `swaps`, `swap`, `swapsBySignature`, `trader`, `token`, `globalStats`, `whaleSwaps`, `swapsRange`, `traderSwaps`, `tokenSwaps` and `health`, all in one schema, so one request can mix them. It is a subset of the REST surface: holders, PnL, tags and everything else are REST only. Use GraphQL when you want several reads in one round-trip, and REST for everything else.

## Endpoint

```
POST https://api.dexploit.dev/graphql
Content-Type: application/json
X-API-Key: ohlcv_live_sk_<your_key>
```

`Authorization: Bearer ohlcv_live_sk_<your_key>` works too. There is no hosted query builder: use any GraphQL client (or `curl`) against this URL with your key header.

## Schema

| Field | Arguments | Returns |
| --- | --- | --- |
| `candles` | `pairAddress: String!` (the pool; `pair_address` in REST), `timeframe: String!` (`1s`, `30s`, `1m`, `5m`, `15m`, `1h`, `4h` or `1d`), `start: String`, `end: String` (RFC 3339 timestamps; `end` defaults to now), `limit: Int` (default `1000`, at most `10000`) | `[GqlCandle!]!`, **oldest first** |
| `protocols` | none | `[String!]!` |
| `swaps`, `swap`, `swapsBySignature`, `trader`, `token`, `globalStats`, `whaleSwaps`, `swapsRange`, `traderSwaps`, `tokenSwaps`, `health` | the filters of the matching REST routes ([`/swaps`](/api-reference), [`/swaps/range`](/api-reference), `/stats/trader`, and so on); introspect the schema for the exact arguments | the REST route's fields, in camelCase |

A `GqlCandle` has `timestamp`, `pairAddress`, `tokenAddress`, `baseMint`, `timeframe`, `open`, `high`, `low`, `close`, `volumeSol`, `volumeToken`, `tradeCount`, `buyCount`, `sellCount`, `uniqueTraders`, `stale` and `pricedAt`: the fields of [`GET /api/v1/candles`](/api-reference), with the same values and units, in GraphQL's camelCase (`volumeSol` is REST's `volume_sol`).

`stale` and `pricedAt` describe the pool's price, the same on every candle of the answer: `stale` is `true` when the pool's last priced trade is more than 600 seconds old, or there is none in the last hour, and `pricedAt` is that trade's time (RFC 3339, `null` if none in the last hour). Both are `null` when you pass `end`. See [Stale prices](/concepts/swap-event-ohlcv#stale-prices).

A request reads at most about **10,000 candles in total**. That's the sum of `limit` over every `candles` in it, aliases included, so two aliases of `6000` are refused as one request. The exact ceiling is 10,500, shared with the request's other fields. A `limit` outside `1`–`10000` is refused with `limit must be <= 10000` (or `limit must be positive`), as it is on REST.

Swaps rows share that ceiling at a higher price: a request may ask for at most **1,500 swaps rows in total** (the sum of `limit` over every swaps list field, aliases included), and each of `trader`, `token`, `swap`, `swapsBySignature` and `globalStats` counts as a fixed 25 of the same budget. The REST limits apply as they do there (for example `swapsRange` windows and the 1,000-row page).

`whaleSwaps` returns the largest swaps by SOL value, and it means the same as `GET /swaps/whale`. Pass `sinceMs` (Unix milliseconds, the REST `since_ms`) to set the start, or `sinceMs: 0` for the all-time size ranking. On a free key a `sinceMs` older than the history window, and `0`, are refused with `HISTORY_WINDOW_EXCEEDED`, as on REST. `minSol` is in lamports (the default is 10 SOL, `10000000000`).

## Rate limits

Each top-level field counts as one request against your per-second rate limit, and a request may hold at most **10** top-level fields (aliases included; more is refused with `too_many_root_fields`). If your key cannot cover all of them, the whole request is refused with HTTP `429` and `Retry-After: 1`, and none of it runs. While the monthly cap is enforced (`monthly_enforced` in [`/credits`](/concepts/quotas-errors#inspecting-your-usage)), each top-level field that is served also counts one request against a Free key's monthly cap; a field that fails is not counted. A JSON array of several operations in one body is not accepted: send one operation per request.

<Warning>
`candles` returns candles **oldest first**, starting at `start`. Without `start` it starts at the pool's **first** candle (on a Free key, at the start of its 14-day window), so `limit: 60` returns the oldest hour from there, not the latest. Pass `start` to get a recent window.
</Warning>

## Sample queries

### The last hour of 1-minute candles

```graphql
query RecentCandles($pair: String!, $start: String!) {
  candles(pairAddress: $pair, timeframe: "1m", start: $start, limit: 60) {
    timestamp
    open
    high
    low
    close
    volumeSol
    tradeCount
  }
}
```

Variables:

```json
{ "pair": "7XawhbbxtsRcQA8KTkHT9f9nc6d69UwqCDh6U5EEbEmX", "start": "2026-09-26T04:40:00Z" }
```

### Two timeframes and the protocol list in one round-trip

Aliases (`minute:`, `hourly:`) let one request ask for the same field twice.

```graphql
query Overview($pair: String!, $lastHour: String!, $lastDay: String!) {
  minute: candles(pairAddress: $pair, timeframe: "1m", start: $lastHour, limit: 60) {
    timestamp
    close
    volumeSol
  }
  hourly: candles(pairAddress: $pair, timeframe: "1h", start: $lastDay, limit: 24) {
    timestamp
    open
    high
    low
    close
  }
  protocols
}
```

Variables:

```json
{
  "pair": "7XawhbbxtsRcQA8KTkHT9f9nc6d69UwqCDh6U5EEbEmX",
  "lastHour": "2026-09-26T04:40:00Z",
  "lastDay": "2026-09-25T05:40:00Z"
}
```

### The protocol list

```graphql
{ protocols }
```

## Schema introspection

Standard GraphQL introspection works. From the command line:

```bash
curl -X POST -H 'X-API-Key: ohlcv_live_sk_<your_key>' \
  -H 'Content-Type: application/json' \
  https://api.dexploit.dev/graphql \
  -d '{"query":"{ __schema { types { name } } }"}'
```

## Errors

An error inside a well-formed query comes back as HTTP `200` with the GraphQL `errors` array. A request body that is not valid JSON is rejected before it runs, with HTTP `400` and the REST [error envelope](/concepts/quotas-errors#response-envelope) (`INVALID_PARAM`).

`trader { stats }` reads the same per-wallet copy as `GET /stats/trader/{wallet}`. When that copy is past its refresh age the HTTP response carries `X-Cache: stale`; see [Stale responses](/concepts/quotas-errors#stale-responses).

## When to use GraphQL vs REST

| Need | Use |
| --- | --- |
| One resource, paginate, possibly cache | REST |
| Several candle series, swaps, trader or token reads in one round-trip | GraphQL |
| Holders, PnL, tags and everything else | REST only |
| WebSocket-style subscriptions | [WebSocket](/streaming/websocket), not GraphQL subscriptions |
