## Response envelope

The envelope is **not uniform across the surface** — it depends on the endpoint family.

**Enveloped (legacy `/api/v1/*` + raw stats/swaps):**

```json
// Success
{ "success": true, "data": { /* payload */ } }

// Error
{ "success": false, "error": { "code": "...", "message": "..." } }
```

These endpoints wrap success payloads: `/api/v1/pairs`, `/api/v1/candles`, `/api/v1/candles/latest`, `/api/v1/stats`, `/api/v1/top-movers`, `/api/v1/protocols` (and the raw `/stats/*`, `/swaps/*` families).

**Top-level (no wrapper):** newer endpoints return the payload directly — no `success`/`data` keys:

- `/screener`, `/search`, `/trending`, `/tokens/{mint}/intel`, `/tokens/{mint}/risk`

For example, `/screener` returns `{ results, total_matches, limit, offset, warnings }` at the top level.

**Errors are always enveloped**, even for the top-level endpoints, and `error` is an object:

```json
{ "success": false, "error": { "code": "INVALID_PARAM", "message": "invalid parameter: invalid_filter:mint" } }
```

Branch on `error.code` ([the codes](#error-codes)). `error.message` is for humans and is not a stable format; a 5xx message is generic and never carries the internal cause.

- `/screener`: a malformed `mint`, `mints[]` or `creator` filter is a 400 `INVALID_PARAM` (message `invalid parameter: invalid_filter:mint|creator|mints`). An *unsupported* filter (e.g. `risk_score`) instead stays **200** and adds a note to the `warnings[]` array.
- `/search`: a malformed `creator` (or `deployer`) or `mints` is a 400 `INVALID_PARAM` (`invalid_filter:creator` or `invalid_filter:mints`). `mint` on `/search` is matched as text, like `query`, and is never rejected. An unsupported filter stays 200 with a `warnings[]` note, as on `/screener`.
- `/tokens/{mint}/intel` and `/tokens/{mint}/risk`: a malformed `mint` is a 400 `INVALID_PARAM`, an unknown mint a 404 `NOT_FOUND`, and a failed lookup a 503 `UNAVAILABLE` (retry). A failed lookup is never reported as a 404; `/tokens/{mint}/risk` answers 504 `GATEWAY_TIMEOUT` if its lookup times out.
- `/tokens/{mint}/holders`, `/holders/top`, `/snipers`, `/insiders`, `/smart-money` and `/whales`: a malformed `mint` is a 400 `INVALID_PARAM` on every tier.
- Not on this shape yet: `/swaps/*` and `/stats/*` send a flat `{ "error": "invalid_parameter", "message": "..." }` (their 401 and 429 carry the `error` object but no `success`), and `/tokens/{mint}/concentration` sends `{ "error": "..." }`. They are being moved to the envelope; until then, if `error` is a string, treat it as the message.

Streaming protocols (WebSocket, gRPC) use protocol-native error frames — see the [WebSocket](/streaming/websocket) and [gRPC](/streaming/grpc) pages.

## Base paths

Endpoints live under different base paths, and one is served by a separate service:

| Family | Base path | Notes |
| --- | --- | --- |
| `candles`, `candles/latest`, `pairs`, `protocols`, `stats`, `top-movers` | `/api/v1/...` | Versioned. |
| `screener`, `trending`, `search`, `tokens/*` (intel, risk, holders, audit, …) | `/` (root) | Unversioned. |
| `tokens/{mint}/audit` | `/` (root) | **Separate backend** — same host (`api.dexploit.dev`). Returns a `200` `indexed: false` sentinel for valid-but-unindexed mints and `400` for malformed mints. |

All paths share the same host, `https://api.dexploit.dev`, and the same `Authorization` / API-key auth.

## Rate limits

Paid tiers are **capped requests-per-second with unlimited monthly usage.** The **Free** tier is capped at 10 requests per second, **10,000 requests per calendar month**, and **14 days of history**. Pick a tier that matches your sustained throughput.

| Tier | Requests per second | Requests per month | History |
| --- | --- | --- | --- |
| Free | 10 | 10,000 | last 14 days |
| Developer | 100 | unlimited | full (see [Coverage](/concepts/coverage)) |
| Pro | 500 | unlimited | full (see [Coverage](/concepts/coverage)) |
| Enterprise | unlimited | unlimited | full (see [Coverage](/concepts/coverage)) |

**Free is strict.** You get 10 requests in any one second, and the 11th gets a 429. Staying quiet beforehand earns no extra.

**Developer and Pro allow short bursts.** Developer sustains 100 requests per second and Pro 500. Developer can send a short burst above its rate, but never more than about 120 in any one second. A burst bigger than the allowance can be refused even when you are under your rate over a whole second, so spread your requests across the second instead of sending a second's worth at once.

Over the limit you get a 429 with `Retry-After: 1`.

## Inspecting your usage

Call `GET /credits` at any time to see your current tier, RPS cap, how much of your per-second allowance is in use, and feature flags:

```json
{
  "tier": "free",
  "rps_cap": 10,
  "rps_window_secs": 1,
  "current_window_used": 7,
  "current_window_remaining": 3,
  "monthly_used": 4321,
  "monthly_used_note": "counted across every API service; resets at monthly_resets_at",
  "monthly_cap": 10000,
  "monthly_remaining": 5679,
  "monthly_resets_at": "2026-11-01T00:00:00Z",
  "monthly_enforced": true,
  "tier_features": {
    "smart_money_access": false,
    "whales_access": false
  }
}
```

On Free, `current_window_used` is the number of requests counted in the current second and `rps_window_secs` is 1. On Developer and Pro the limit is a rate, so `current_window_used` is how much of your allowance is in use right now, on the same scale as `rps_cap`: 0 when you have been idle, and `rps_cap` when it is used up and the next request would get a 429. It is not a count of the requests in the last second, and `rps_window_secs` (still 1) is not a window you are counted in. `current_window_remaining` is `rps_cap` minus `current_window_used`.

`monthly_used` is your cumulative request count for the current calendar month. On paid tiers `monthly_cap`, `monthly_remaining` and `monthly_resets_at` are `null` and `monthly_enforced` is `false`; the count is informational, so you can size up your typical load. On the Free tier the cap is 10,000 requests per month and `monthly_resets_at` is 00:00 UTC on the 1st. The cap is applied only while `monthly_enforced` is `true`.

## Rate limiting

When you go over your tier's limit you get HTTP 429 with `code: "RATE_LIMIT_EXCEEDED"` and a `Retry-After: 1` header. Wait that long and retry; [`GET /credits`](#inspecting-your-usage) shows how much of your allowance is in use.

## Free-tier monthly cap and history window

While `monthly_enforced` is `true` in [`/credits`](#inspecting-your-usage), a Free key that has used its 10,000 requests for the calendar month gets HTTP 429 with `code: "MONTHLY_QUOTA_EXCEEDED"`. The error carries `error.limit`, `error.used` and `error.reset_at`, where `reset_at` is an RFC 3339 timestamp, 00:00 UTC on the 1st (for example `"2026-11-01T00:00:00Z"`). Retrying sooner will not help; wait for the reset or upgrade.

A Free key whose request **names a time** older than 14 days gets HTTP 403 with `code: "HISTORY_WINDOW_EXCEEDED"`. A request that names no time is not trimmed to the window. The time can be a `start`/`end`, `from`/`to`, `timestamp`, `start_time`/`end_time`, `since_ms`, `before`, a pagination `cursor`, or a swap looked up by a signature older than that. The error carries `error.oldest_allowed` (RFC 3339 UTC, the earliest time the key may request) and `error.window_days`:

```json
{
  "success": false,
  "error": {
    "code": "HISTORY_WINDOW_EXCEEDED",
    "message": "The free tier serves the last 14 days of history. The oldest time you can request is 2026-09-29T04:36:31.845Z.",
    "oldest_allowed": "2026-09-29T04:36:31.845Z",
    "window_days": 14
  }
}
```

GraphQL returns the same three keys (`code`, `oldest_allowed`, `window_days`) in `errors[].extensions`.

The history check applies to these endpoints:

| Service | Endpoint | Time parameter |
| --- | --- | --- |
| Swaps | `/swaps` | `signature` (the swap's own time) |
| Swaps | `/swaps/range` | `start_time`, `end_time`, or `signature` (the swap's own time) |
| Swaps | `/swaps/whale` | `since_ms` (`0` or less means the beginning of time) |
| Swaps | `/swaps/{signature}` | the swap's own time |
| Swaps | `/swaps/trader/{wallet}`, `/swaps/token/{mint}` | `cursor` |
| Swaps | `/pool-events` | `before` |
| OHLCV | `/api/v1/candles` | `start`, `end` |
| OHLCV | `/price/history/timestamp` | `timestamp` |
| OHLCV | `/price/history/range` | `from`, `to` |
| OHLCV | `/holders/chart/{token}`, `/snipers/chart/{token}`, `/insiders/chart/{token}`, `/bundlers/chart/{token}`, `/tokens/{mint}/actor-chart` | `from`, `to` |

The GraphQL equivalents are checked the same way. `/price/history`, `/chart/{token}`, `/api/v1/candles/latest` and aggregates are not windowed. Ask for a time inside the window, or upgrade for full history. Paid keys are not affected by either limit.

## Tier-locked features

Some endpoints are paid-tier-only. Free tier callers get **HTTP 200 with `tier_locked: true`** rather than a 429:

```json
{
  "mint": "BoMb…",
  "results": [],
  "tier_locked": true,
  "tier_required": "developer",
  "upgrade_url": "https://dexploit.dev/pricing",
  "computed_at": 1779852398772
}
```

This keeps client code simple — same response shape, an extra flag — and lets your UI render an upsell where data would be without an error-handling branch.

Currently tier-locked endpoints: `/tokens/{mint}/smart-money`, `/tokens/{mint}/whales`.

## Streaming caps

Each API key has one allowance of concurrent streams, set by its tier. Every open stream on every transport counts against it: a gRPC `dexploit.v1.SwapStream` stream, a gRPC `dexploit.v1.PriceStream` stream, and a `/ws` or `/ws/swaps` WebSocket.

| Tier | Max concurrent streams per key |
|---|---|
| Free | 1 |
| Developer | 10 |
| Pro | 50 |
| Enterprise | unlimited |

The allowance is counted per streaming server today, so while your streams are spread across servers you may be allowed more than your tier's cap. Do not rely on that: the cap will be enforced across all servers.

Opening a stream past the cap is refused once the cap is reached on the server that receives it: gRPC returns `RESOURCE_EXHAUSTED` (`stream cap exceeded; tier=… cap=…`), and a WebSocket is closed with code `1013`. A slot is freed once the server sees the stream close, which can take a few seconds after your client disconnects. A client that reconnects immediately can therefore still get `RESOURCE_EXHAUSTED` (or `1013`): wait a few seconds, or retry with a short backoff.

The `wallet_tags` filter is Pro+ only — on lower tiers the filter is silently dropped and the response carries `x-dexploit-tier-locked-filter: wallet_tags` metadata. See [gRPC: SwapStream](/streaming/grpc-swaps) for the full reference.

## Error codes

| Code | Status | Meaning | Remedy |
| --- | --- | --- | --- |
| `UNAUTHORIZED` | 401 | Key missing, malformed, or revoked. | Generate a new key in the dashboard. |
| `FORBIDDEN` | 403 | Authenticated, but not allowed. | Check your tier; some endpoints require Pro or Enterprise. |
| `RATE_LIMIT_EXCEEDED` | 429 | Over your tier's per-second limit. | Wait the `Retry-After` seconds (1) and retry. |
| `MONTHLY_QUOTA_EXCEEDED` | 429 | Free tier: the 10,000-requests-per-month cap is used up. | Wait for the reset time in the response, or upgrade. |
| `HISTORY_WINDOW_EXCEEDED` | 403 | Free tier: the request names a time older than 14 days. | Use a time on or after `oldest_allowed`, or upgrade. |
| `RATE_LIMITED` | 429 | The edge's own limits: more than 500 requests per second on one key, or too many attempts on an authentication endpoint. | Back off and retry. On a 429, branch on the status, since both codes mean "slow down". |
| `INVALID_PARAM` | 400 | One of your query params is wrong. | See `error.message`. The most common cause is sending `mint` to `/candles` — use `pair_address`. |
| `MISSING_PARAM` | 400 | A required param is absent. | Add it. |
| `NOT_FOUND` | 404 | Resource doesn't exist (e.g., unknown mint or `pair_address`), or no such path under an endpoint's prefix. A path outside the API's routes can be a 404 with an empty body instead. | Verify via [`/api/v1/pairs`](/api-reference). |
| `METHOD_NOT_ALLOWED` | 405 | The path exists, but not for this HTTP method. | Use the method the API reference lists; most endpoints are `GET`. |
| `UNAVAILABLE` | 503 | Backend dependency is down. | Retry with backoff. |
| `GATEWAY_TIMEOUT` | 504 | Upstream took too long. | Retry; reduce `limit` if persistent. |
| `INTERNAL` | 500 | Server-side error. | Retry. If it persists, [contact support](https://www.dexploit.dev/contact). |
