<Update label="2026-10-07" description="Breaking: GET /swaps/{signature} returns every swap of the transaction">
**Breaking.** `GET /swaps/{signature}` now answers with an envelope that holds every swap of the transaction, instead of one swap object.

```json
{ "signature": "2B9pP1c1…", "total": 2, "swaps": [ { "…": "swap object" }, { "…": "swap object" } ], "price_semantics": "…" }
```

- **Why:** a signature names a transaction, and a transaction can hold more than one swap (a multi-hop route, or swaps on several venues). In one measured hour (2026-10-07, 17:00 to 18:00 UTC) 6.0% of transactions did, and the largest held 13 swaps. The route used to answer with one of them, chosen arbitrarily, and hid the rest.
- **Migrate:** read the swap fields you used from each element of `swaps`. Each element is the swap object the route returned before, with the same fields. A transaction with one swap gives a one-element array, so a client that reads `swaps[0]` sees what it saw before for those.
- **Order:** `swaps` is in a fixed order (ascending `slot`, `block_tx_index` and `ix_index`, then `dex`), so the same request returns the same order. `total` is always `swaps.length`: the swaps of one transaction are not paged.
- **`price_semantics` moved.** It is now a field of the response body, as on the other `/swaps*` routes. The `x-price-semantics` response header is no longer sent.
- **Unchanged:** an unknown signature is still a 404, and a lookup that ran out of time is still a 503, never a 404.
- **Now documented on the swap object:** `ix_index` and `block_tx_index`. The API already returned them on every swap; they are the keys the order is built from.
</Update>

<Update label="2026-10-07" description="Additive: time-lock keys on the audit lock object">
**Additive.** The `lock` object of a token's audit (`GET /tokens/{mint}/audit`, and `audit` on `GET /tokens/{mint}`) can now say that the LP is locked for a limited time and until when. A client that ignores keys it does not know is unaffected.

- **New keys:** `kind` (`"time_lock"`), `unlock_at`, `status` (`"active"` or `"expired"`) and `time_locked_pct` (`{ value, status, as_of }`). They appear only when a time lock is known for the token's pool (today: UNCX concentrated-liquidity locks) and only on a `lock` that already exists. They never raise `secured_pct`.
- **How to read them:** `mechanism` and `secured_pct` still describe a *permanent* arrangement only. `mechanism: "unsecured"` beside `kind: "time_lock"` and `status: "active"` means nothing is permanent and the LP is locked until `unlock_at`. `status: "expired"` means the owner can withdraw at any moment. `time_locked_pct.value` is a share of that pool's position value at `as_of`, not of liquidity; the `lock` object's description under `GET /tokens/{mint}/audit` has the full reading.
- **Clarified:** `mechanism: "locked"` and `lp_burnt: true` mean a permanent lock (a burn, Raydium Burn&Earn, a Meteora DAMM v2 permanent lock). A time-limited lock (UNCX, Streamflow, Jupiter Lock) does not count as either. The previous description listed them under `locked`.
</Update>

<Update label="2026-09-29" description="Breaking: one error body">
**Breaking.** Endpoints that answered an error with `{ "success": false, "data": null, "error": "<string>" }` now answer with the documented envelope, where `error` is an object:

```json
{ "success": false, "error": { "code": "MISSING_PARAM", "message": "missing required parameter: pair_address" } }
```

- **Migrate:** branch on `error.code` ([the codes](/concepts/quotas-errors#error-codes)) instead of parsing the `error` string. The message text of a 4xx is unchanged.
- **Every error of these endpoints is now the envelope.** That includes the ones that had an empty body (a 400 over a batch cap, a 500, a wrong method) or a plain-text body (a query parameter that does not parse, or a `/graphql` request body that is not valid JSON). A path outside the API's routes can still be a 404 with an empty body.
- **New codes:** a missing query parameter is `MISSING_PARAM`, and a wrong HTTP method is a 405 `METHOD_NOT_ALLOWED`.
- **A 5xx message is now generic.** It no longer carries the internal cause; retry on `UNAVAILABLE`, `GATEWAY_TIMEOUT` or `INTERNAL`.
- **A malformed mint is a 400.** On `/tokens/{mint}/holders`, `/holders/top`, `/snipers`, `/insiders`, `/smart-money` and `/whales` it is a 400 `INVALID_PARAM` on every tier; before, it was an empty 200.
</Update>
