<Update label="Pending deploy" description="Breaking: /swaps/{signature} returns every leg of the transaction">
**Breaking.** `GET /swaps/{signature}` now returns an envelope with every swap of the transaction, instead of one swap object. A signature names a transaction, and about 1 in 21 transactions holds more than one swap (multi-hop and multi-venue routes); the route used to return one of them, not always the same one.

```json
{ "signature": "<signature>", "total": 2, "swaps": [ { "signature": "<signature>", "dex": "pumpswap" }, { "signature": "<signature>", "dex": "raydium_cpmm" } ], "price_semantics": "pool_price=RAW vault ratio, uncorrected (not a tradeable price); ..." }
```

- **Migrate:** read `swaps` (an array). When `total` is `1`, `swaps[0]` is the object the route used to return.
- **Order:** `swaps` is ordered by `slot`, `block_tx_index`, `ix_index`, then `dex`, and is the same on every call.
- **The `x-price-semantics` header is gone.** The label is the `price_semantics` field of the body, like the other swap routes, so a browser can read it.
- **`404`** only when no swap has that signature. A lookup that does not finish in time is a `503` with `Retry-After`, never a `404`.
</Update>

<Update label="2026-09-29" description="Breaking: one error body">
**Breaking.** Endpoints that answered an error with `{ "success": false, "data": null, "error": "<string>" }` now answer with the documented envelope, where `error` is an object:

```json
{ "success": false, "error": { "code": "MISSING_PARAM", "message": "missing required parameter: pair_address" } }
```

- **Migrate:** branch on `error.code` ([the codes](/concepts/quotas-errors#error-codes)) instead of parsing the `error` string. The message text of a 4xx is unchanged.
- **Every error of these endpoints is now the envelope.** That includes the ones that had an empty body (a 400 over a batch cap, a 500, a wrong method) or a plain-text body (a query parameter that does not parse, or a `/graphql` request body that is not valid JSON). A path outside the API's routes can still be a 404 with an empty body.
- **New codes:** a missing query parameter is `MISSING_PARAM`, and a wrong HTTP method is a 405 `METHOD_NOT_ALLOWED`.
- **A 5xx message is now generic.** It no longer carries the internal cause; retry on `UNAVAILABLE`, `GATEWAY_TIMEOUT` or `INTERNAL`.
- **A malformed mint is a 400.** On `/tokens/{mint}/holders`, `/holders/top`, `/snipers`, `/insiders`, `/smart-money` and `/whales` it is a 400 `INVALID_PARAM` on every tier; before, it was an empty 200.
</Update>
